# ПРАВИЛА РАЗРАБОТКИ ИНЖЕНЕРНОГО ЯДРА (СКЛАДЫ ВМ РК)

1. **Строгая юрисдикция (Республика Казахстан):**
   Все расчеты и проверки опираются ИСКЛЮЧИТЕЛЬНО на:
   - Приказ МИР РК от 30.12.2014 № 343 (в ред. Приказа МИР РК № 895 от 22.12.2017 и Приказа МЧС РК № 120 от 17.03.2023); эталонный текст — `Documentation/v1400010244.02-10-2025.rus.pdf` (ред. на 02.10.2025), все расчеты и таблицы сверяются с ним;
   - ТР ТС 028/2012 (Приложение № 3 — группы совместимости ВМ).
   КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО использовать коэффициенты, формулы и нормы из законодательства РФ (ФНП РФ Приказ № 528 и др.) или придумывать недостающие значения.

2. **Никаких «магических чисел» в логике:**
   Любой нормативный предел (метры, килограммы, коэффициенты) должен быть объявлен как именованная константа в `src/explosions_core/norms/constants_rk343.py` с комментарием, указывающим точный пункт Приказа № 343, и зарегистрирован в `norms/sources.py` со статусом сверки (тест проверяет полноту). Допущения, которых нет в тексте НПА, записываются в `docs/assumptions.md`.

3. **Обязательная трассировка ошибок:**
   Любая ошибка валидации проектного решения должна возвращать объект `NormativeViolation`, содержащий:
   - `code`: уникальный код ошибки;
   - `clause`: точная ссылка на пункт НПА (например, "п. 579 Приказа МИР РК № 343"), взятая из единого реестра `src/explosions_core/norms/references.py` (строки ссылок в модулях не дублировать);
   - `actual_value` и `required_value`: фактическое и нормативное значения.

4. **Архитектура и стек:**
   - Python 3.11+, строгая типизация (`typing`, `pydantic>=2.0`).
   - Вычислительное ядро (`src/explosions_core/calc/`) и доменная модель (`src/explosions_core/domain/`) не должны зависеть от UI, веб-фреймворков и модулей экспорта (`export/`).
   - Каждая новая функция сопровождается модульным тестом на `pytest` (подход TDD).
   - Если формула или таблица коэффициентов из Приложения 11 еще не передана пользователем в промпте — ставь `raise NotImplementedError("Требуется таблица из Приложения 11 Приказа № 343")`, НИКОГДА не угадывай формулу сам.

5. **Целевая платформа — корпоративная Windows в домене AD:**
   - Целевая ОС: Windows 11 Pro/Enterprise, рабочая станция в домене Active Directory (у пользователя есть права локального администратора).
   - Пути профилей пользователей домена и названия ВМ могут содержать кириллицу — код обязан корректно работать с ними.

6. **Работа с путями и кодировками:**
   - Во всех модулях используй исключительно `pathlib.Path`. Запрещено склеивать пути строками и жестко зашивать разделители `/` или `\` (а также использовать `os.path.join` с литералами-разделителями).
   - При чтении и записи ЛЮБЫХ текстовых файлов (`.json`, `.dxf`, `.txt`, `.csv`, отчетов) всегда явно указывай `encoding="utf-8"`: `Path.read_text(encoding="utf-8")`, `Path.write_text(..., encoding="utf-8")`, `open(path, "w", encoding="utf-8")`. Полагаться на кодировку по умолчанию (`cp1251`) запрещено.
   - Для `ezdxf` при сохранении/чтении указывай кодировку явно (`doc.saveas(path, encoding="utf-8")`, `ezdxf.readfile(path, encoding="utf-8")`), путь передавай как `pathlib.Path`.

7. **Запуск команд в терминале:**
   - Групповые политики (GPO) домена могут запрещать выполнение `.ps1`-скриптов PowerShell. НЕ используй `Activate.ps1` и любую активацию окружения через скрипты.
   - Все команды запускай напрямую через интерпретатор виртуального окружения проекта `.venv`:
     - тесты: `.\.venv\Scripts\python.exe -m pytest`
     - установка пакетов: `.\.venv\Scripts\python.exe -m pip install <пакет>`
   - При ошибке корпоративного SSL-сертификата домена при `pip install` используй системное хранилище сертификатов Windows:
     `.\.venv\Scripts\python.exe -m pip install --use-feature=truststore <пакет>`

8. **Архитектура интерфейса и упаковки (будущие этапы):**
   - ЗАПРЕЩЕНО использовать веб-фреймворки (`Streamlit`, `FastAPI`, `Flask` и аналоги) и любые локальные HTTP-серверы: нельзя открывать сетевые порты (`localhost`), чтобы не вызывать срабатываний доменного брандмауэра Windows Defender.
   - GUI финального этапа — нативное десктопное окно Windows на `PySide6`.
   - Сборка исполняемого файла — `PyInstaller` строго в режиме каталога `--onedir` (без `--onefile` и распаковки во временную папку `%TEMP%`), чтобы не конфликтовать с политиками AppLocker и корпоративным антивирусом.

9. **Структура проекта (src-layout, пакет `explosions_core`):**
   - `norms/` — нормативные константы (`constants_rk343.py`), реестр ссылок на НПА (`references.py`), справочные таблицы (`data/*.json`).
   - `domain/` — модели Pydantic v2 по предметным областям (`enums`, `results`, `explosives`, `storage`, `sizing`, `distances`, `berm`, `lightning`); импорт моделей — из `explosions_core.domain`.
   - `validators/` — детерминированные проверки (совместимость, планировка, периметр, ПРП, склады).
   - `calc/` — расчетные модули (габариты, безопасные расстояния, обвалование, молниезащита, геометрия).
   - `export/cad/` (DXF) и `export/reports/` (DOCX) — генераторы выходных документов.
   - `gui/` — интерфейс PySide6 (окна, формы, генплан). Только импортирует ядро и `pipeline`; логику расчета и правила проверки здесь не дублировать. `session.py` и `labels.py` не зависят от Qt. Вывод интерфейса — без сетевых портов, веб-фреймворков и без `Activate.ps1`.
   - `tests/` — тесты `pytest`; эталонные исходные данные — `tests/fixtures/`, общие фикстуры — `tests/conftest.py`.
   - Ресурсы пакета ищутся только через `Path(__file__)`, без привязки к текущему каталогу.
